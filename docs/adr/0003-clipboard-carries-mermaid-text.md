# 0003 — クリップボードは Mermaid テキストを運ぶ（専用形式を作らない）

Status: Accepted (2026-09-22)

## Context

キャンバス上の選択範囲をコピー＆ペーストしたい。運ぶ中身として2案あった。

1. 選択範囲を表す専用のシリアライズ形式（IR の部分木を JSON 等で）
2. 選択範囲から生成した Mermaid テキスト

案1は「選択したものをそのまま復元できる」点で素直に見える。ただし ADR 0001
は **マスターはひとつ（IR）／テキストはその投影** と定めており、専用形式を
足すと「IR でも Mermaid テキストでもない第3の表現」が増える。図種が増える
たびに3つ目の入出力を書き足すことになり、Mermaid と食い違ったときにどちらが
正しいかを決める根拠もない。

## Decision

**クリップボードは Mermaid テキストを運ぶ。** コピーは既存の codegen、
ペーストは既存の parser をそのまま使い、新しいエミッタもリーダも書かない。

- コピーしたものはコードペインにも他の Mermaid ツールにも貼れる。
- 他所で拾った Mermaid テキストをキャンバスに貼れる。
- 図種の追加でクリップボード用の実装が増えない。

実装は `@gmermaid/clipboard`（`ir` の上、`xstate` と同じ階層）。`ir` に置け
ないのは、生成と解析の両方に依存して循環するため。

## Consequences

**本質的な作業は「閉包」になる。** 選択範囲は単体では成立しないことが多い。
辺だけ選んでも両端の宣言が要り、メッセージだけ選んでもライフラインが要る。
図種ごとの閉包規則を決めて明文化する必要がある（`clipboard.ts` ヘッダに記載）。

**テキストで表せないものは運べない。** XState 固有の情報（entry/exit、invoke、
guard、context）は Mermaid が綴れないため、コピーには乗らない（ADR 0002）。
元の図は保持し、コピーは Mermaid 側の半分になる。

**表現できない選択は拒否する。** Mindmap の互いに繋がらない2つの部分木は、
Mermaid のアウトライン記法では1本の木しか書けないため運べない。根を合成すると
利用者が作っていない内容を発明することになるので、拒否を選ぶ。

**図全体の設定はコピーされてもペーストされない。** `direction` や gantt の
`dateFormat` はテキストを単体で成立させるために付くが、貼り付け先の図の向きや
日付書式を書き換えてはならないため無視する。
